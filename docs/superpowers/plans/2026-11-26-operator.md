# Self-service P4a: the operator's side — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Console admins can find and manage self-service tenants and users:
- list tenants;
- change a tenant's quota;
- suspend and unsuspend tenants and users;
- resend a verification email;
- force a factor reset.

This happens through a new Portal operator API, with email to the people affected and audit on
both sides.

**Architecture:**
- The Portal exposes `/api/operator/*` behind `x-operator-key`.
- The Console orchestrates every action. It calls AuthGate first, with the admin key, and the
  Portal second, with the operator key.
- The Console never reads the Portal's table.
- Shared code goes through `internal/platform`: a new `portalapi` client, the moved `avatar`
  package, and an `auditlog` result override.

**Tech Stack:** Go 1.x with DynamoDB, React 19 with Mantine 7, SAM/CloudFormation, Bruno, and
bash scripts.

**Spec:** `docs/superpowers/specs/2026-11-26-operator-design.md`. It refines §10 of
`docs/superpowers/specs/2026-11-22-self-service-design.md`.

## Global Constraints

- Any Console admin may run operator actions. Each needs step-up and is audited. `admin-*`
  actions stay master-only (`internal/console/stepup.go:186`).
- **Operator key:**
  - SSM SecureString `/credo/auth-gate-portal/<stage>/operator-key`, sent as the header
    `x-operator-key`.
  - Checked with `httpx.RequireKey("x-operator-key", httpx.StaticKey(key))`. A missing or wrong
    key answers `401 {"error":"unauthorized"}`.
  - Rate-limited per key, with `ratelimit.Settings{Burst: 60, PerSecond: 1}`, under bucket key
    `operator`.
- **Suspension reason:** 1 to 200 characters after trimming, required for `tenant-suspend` and
  `user-suspend`. It is stored only in the Console audit detail `reason`. It never goes to the
  Portal or to an email.
- **Order:** tenant suspend, unsuspend and quota call AuthGate first, then the Portal. When
  AuthGate succeeds and the Portal fails, the Console answers the Portal's error and its audit
  entry's result is `partial`.
- **Tenant audit actor in the Portal:** `actorId "operator"`, `actorName "AuthGate administrator"`.
  portal-web shows `actorId === 'operator'` as `t.audit.operatorActor` (EN "AuthGate
  administrator", VI "Quản trị viên AuthGate").
- **New mail kinds:** `tenant-suspended`, `tenant-unsuspended`, `account-suspended`,
  `account-unsuspended`, in EN and VI.
  - Fixed text plus `org` (the tenant name, or the personal label) where it applies.
  - Each mail ends with the support line.
  - No sign-in button and no "change your password" footer.
- **Idempotent writes:** a repeated suspend, unsuspend or resend answers `200` and sends no
  second email.
- **Suspended tenant:** every workspace write answers `409 tenant_suspended`, except leaving an
  org. The code already exists in portal-web.
- **No new deployer policy.**
  - `infra/role-boundary.json` gains `auth-gate-console-*/avatars/*` and `/pending/*`.
  - CI deploys the Portal before the Console.
- **Fixed monthly cost:** none.
- **Engineering rules:**
  - Tests only where a failure would do real harm, each with a `// Why:` comment.
  - English, Conventional Commits, trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - Gate: `PATH="$HOME/go/bin:$PATH" pnpm run check` exits 0.
  - Go tests that need DynamoDB run with `docker compose up -d dynamodb` and
    `DYNAMO_ENDPOINT=http://localhost:8000`.

## Review Focus

1. **A deleted or deleting tenant.** An operator who opens it, or suspends it, gets `404` for a
   tenant that is gone, and a deleting tenant shows status "deleting" with no suspend action.
   Task 4 test.
2. **Suspending the Portal's own operator-facing pieces.** The operator suspends the tenant that
   owns no client, or a personal tenant. That works, and the owners are emailed (a personal
   tenant's owner is its user). Task 4 test.
3. **A suspended user who is a tenant's only owner.** The tenant keeps working for its other
   members, while the user is signed out on their next request. Task 4 test.
4. **An email with different case or spaces in the Users search.** It finds the user, because
   `GetUserByEmail` normalises. Task 3 test.
5. **The Portal down during a Console suspend.** The Console answers an error, AuthGate shows the
   tenant suspended, the audit says `partial`, and pressing suspend again finishes the Portal
   step with no second AuthGate error. Task 7 test.

- Produces:
  - `POST /api/operator/tenants/{tid}/suspend` and `/unsuspend`. The body is `{}`. The answer is
    the tenant row.
    - Suspend sets `suspendedAt` with the condition `attribute_not_exists(suspendedAt)`;

    - Only a write that changed state writes the tenant audit and sends the mail:
      - the audit entry has `actorId "operator"`, `actorName "AuthGate administrator"`, action

      - the mail goes to every owner, with `org` set to the name, or the personal workspace

    It writes the audit entry with detail `from` and `to`, and answers `204`. Any other action
    answers `400 invalid_action`.
  - `POST /api/operator/users/{uid}/suspend` and `/unsuspend`.
    - Suspend is one `UpdateItem`: `SET suspendedAt = :t ADD sessionEpoch :one`, with the
      condition `attribute_not_exists(suspendedAt)`. Unsuspend is `REMOVE suspendedAt`.
    - Mail `account-suspended` or `account-unsuspended`, only when the state changed.
    - The answer is the user view from Task 3.
  - `POST /api/operator/users/{uid}/resend-verification`: `sendVerify(ctx, u)` (`signup.go:116`).
    A verified user answers `409 already_verified`.
  - `POST /api/operator/users/{uid}/factor-reset`:
    - `PutFactorReset(ctx, uid, now, now+factorResetWait)`, then mail `factor-reset-started`
      with `until`, only when `created`;
    - an unverified or suspended user answers `409 not_mailable`;
    - the answer is `{dueAt}`.
