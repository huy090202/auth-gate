# Self-service P4b: the WAF, built but off — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a CloudFront web ACL that ships off and costs nothing. The owner switches it on and off
with scripts. CI keeps it attached while it is on and never creates it. A 10 USD monthly cost
alert comes with it.

**Architecture:**
- A stack `auth-gate-waf-<stage>` in us-east-1 holds the web ACL.
- An SSM parameter in the app region is the switch.
- The three app stacks take an optional `WebAclArn` parameter. The deploy scripts fill it from
  the switch on every deploy.
- `enable.sh` and `disable.sh` run under the admin profile. They create and delete the WAF stack
  and the switch. The attach or detach itself happens in a CI deploy that the owner starts by hand.

**Tech Stack:** CloudFormation (WAFv2, `Scope: CLOUDFRONT`), bash with hermetic stub tests (the
`scripts/*/test/*.sh` pattern), GitHub Actions, AWS Budgets.

**Spec:** `docs/superpowers/specs/2026-11-28-waf-design.md`. This plan amends §3: see "Ruling"
below.

**Ruling (amends spec §3 steps 4 and 3):** `enable.sh` and `disable.sh` do not run the three app
deploys on the owner's machine. Those deploys need `EMAIL_FROM`, `TURNSTILE_SITE_KEY` and a full
build, and running them locally would never prove that the CI deployer's IAM can attach the web
ACL. Instead:
- `ci.yml` gains `workflow_dispatch` on main.
- `enable.sh` ends by telling the owner to run the `ci` workflow on main from the Actions tab.
  That deploy attaches the web ACL.
- `disable.sh` works in two phases:
  - **Phase 1:** it deletes the switch and tells the owner to run the workflow, which detaches
    the web ACL.
  - **Phase 2:** the same command, run again, checks that no distribution still uses the web ACL
    (`cloudfront list-distributions-by-web-acl-id`), then deletes the stack.

## Global Constraints

> Note: the controller ruling replaced the empty default for `WebAclArn` with the sentinel `none` (pattern `^none$|^arn:...`, `HasWaf` = not `none`). Lines below that say empty, `^$|` or `WebAclArn=` are superseded.

- The stack is `auth-gate-waf-<stage>` in `us-east-1`. The web ACL is named `auth-gate-<stage>`,
  with `Scope: CLOUDFRONT`, default action Allow, and output `WebAclArn`.
- The four rules, in priority order:

  | Priority | Name | Statement | Action |
  |---|---|---|---|
  | 0 | `ip-reputation` | managed group `AWSManagedRulesAmazonIpReputationList` | none (block) |
  | 1 | `common` | managed group `AWSManagedRulesCommonRuleSet` | none (block), with `RuleActionOverrides` setting `SizeRestrictions_BODY` to Count |
  | 2 | `rate-browser` | rate-based, `Limit: 300`, `EvaluationWindowSec: 300`, aggregate by IP | block |
  | 3 | `rate-all` | rate-based, `Limit: 6000`, `EvaluationWindowSec: 300`, aggregate by IP, no scope-down | block |

  Rule 2's scope-down matches the Host header starting with `portal.` or `admin.`, lowercased.
  Every rule and the ACL have `VisibilityConfig` with CloudWatch metrics on and sampled requests
  on. There is no logging configuration.
- The switch is an SSM String parameter, `/credo/auth-gate/<stage>/waf-acl-arn`, in the app region
  (`ap-southeast-1`). If the parameter is present, the WAF is on.
- The app stacks get a parameter `WebAclArn`:
  - default `""`;
  - `AllowedPattern: "^$|^arn:aws[a-zA-Z-]*:wafv2:us-east-1:\\d{12}:global/webacl/.+$"`;
  - a condition `HasWaf`;
  - in the distribution, `WebACLId: !If [HasWaf, !Ref WebAclArn, !Ref AWS::NoValue]`.
- The deploy scripts read the switch on every deploy. `ParameterNotFound` means off, so they pass
  `WebAclArn=`. Any other error stops the deploy, and nothing is passed.
- The cost text that `enable.sh` prints, verbatim:
  `about 9-10 USD a month while on (5 USD web ACL + 4 rules x 1 USD + 0.60 USD per million requests)`
- The typed confirmations are `enable <stage>` and `disable <stage>`, read from stdin, with exact
  match.
- The budget is named `auth-gate-monthly`: COST, MONTHLY, 10 USD. It notifies at
  FORECASTED > 80% and at ACTUAL > 100%. The address comes from `BUDGET_EMAIL` and is never
  printed. The script prints `created` or `exists`.
- Admin scripts use `ADMIN_PROFILE` (default `default`), as `scripts/setup-and-deploy/0x-*.sh` do.
- No secret or email goes on argv. A value that has to be written goes through a 0600 file and
  `--cli-input-json`, as `scripts/portal/operator-key.sh` does. The email address does go into a
  JSON file, never on argv.
- Engineering rules:
  - Tests only where a failure would do real harm, each with a `# Why:` comment.
  - English. Conventional Commits with the trailer
    `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
  - New scripts and tests are added to `package.json` `lint` (shellcheck globs) and `test`.
  - Gate: `PATH="$HOME/go/bin:$PATH" pnpm run check` exits 0.
  - Never call real AWS. Stub `aws` and `sam` as `scripts/domain/test/03-deploy.sh` does.

## Review Focus

1. **The SSM read fails for a reason other than "not found" while the WAF is on**, for example a
   throttle or access denied. The deploy must stop, not detach the WAF quietly. Tested in Task 2.
2. **`disable.sh` phase 2 runs while a distribution still uses the web ACL**, because the owner
   skipped the CI run. It must refuse to delete the stack, name the distributions, and say to run
   the workflow. Tested in Task 3.
3. **A wrong or wrong-stage confirmation**, such as `enable prod` on stg, `Enable stg` or an empty
   line. Nothing changes and the script exits non-zero. Tested in Task 3.
4. **A half-done enable:** the stack exists but the switch is absent, because the earlier run died
   after the stack. Re-running `enable.sh` completes it with no error. Tested in Task 3.
5. **`budget.sh` run without `BUDGET_EMAIL`**, or run a second time. The first refuses before any
   AWS call. The second prints `exists`. The address never appears in output or on argv. Tested
   in Task 4.

### Task 3: `enable.sh`, `disable.sh` and the manual CI run

**Files:**
- Create:
  - `scripts/waf/enable.sh`;
  - `scripts/waf/disable.sh`;
  - `scripts/waf/test/switch.sh`.
- Modify `.github/workflows/ci.yml`:
  - add `workflow_dispatch:` to `on:`;
  - change the deploy job's `if` (~47) to
    `(github.event_name == 'push' || github.event_name == 'workflow_dispatch') && github.ref == 'refs/heads/main'`.

**Interfaces:**
- Both scripts:
  - take `STAGE` (default `stg`) and `ADMIN_PROFILE` (default `default`);
  - read the confirmation line from stdin;
  - CloudFormation calls use `--region us-east-1`, and SSM calls use the app region.
- `enable.sh` steps:
  1. Print the plan and the cost text, then read the confirmation.
  2. `aws cloudformation deploy --template-file infra/waf.yaml --stack-name auth-gate-waf-$STAGE --region us-east-1 --parameter-overrides Stage=$STAGE --tags app=auth-gate --no-fail-on-empty-changeset`.
  3. Read the `WebAclArn` output.
  4. `ssm put-parameter --type String --overwrite` for the switch.
  5. Print the next step, exactly:
     `Next: GitHub → Actions → ci → Run workflow (branch main). That deploy attaches the web ACL.`
- `disable.sh`, with the phase chosen by state:
  - **Switch present (phase 1):** confirm, delete the switch, then print
    `Next: run the ci workflow on main to detach the web ACL, then run disable.sh again to delete the stack.`
  - **Switch absent and stack present (phase 2):**
    1. Confirm.
    2. Read the ACL id from the stack output, then
       `cloudfront list-distributions-by-web-acl-id --web-acl-id <arn>`.
    3. If any distribution still uses it, print the distribution ids and the same "run the
       workflow" line, then exit 1 (Review Focus 2).
    4. Otherwise run `cloudformation delete-stack`, then `wait stack-delete-complete`, then print
       `WAF off: no web ACL, no WAF cost.`
  - **Neither present:** print `already off` and exit 0.
