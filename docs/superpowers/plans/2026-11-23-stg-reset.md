# Reset stg's user data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An operator command that deletes stg's user data across four tables and the avatar bucket, and keeps the three app clients, the Console admins and their factors.

**Architecture:**
- A pure rule function decides keep or delete per item.
- A runner scans each table with a small projection, applies the rule, and batch-deletes (only with apply) after it has checked the keep set against AuthGate.
- `cmd/stg-reset` wires flags to the runner.
- `08-reset-data.sh` reads the keep set from the stacks, handles the S3 avatars, and asks for the typed confirmation.

**Tech Stack:** Go with aws-sdk-go-v2 (dynamodb), DynamoDB Local tests, bash with stub-`aws` tests.

**Spec:** `docs/superpowers/specs/2026-11-23-stg-reset-design.md`

## Global Constraints

- Stage must be `stg`. The wrapper and the command both refuse any other value.
- Tables: `auth-gate-<stage>`, `auth-gate-console-<stage>`, `auth-gate-portal-<stage>`, `auth-app-<stage>`. Bucket: the `AvatarBucket` output of `auth-gate-portal-<stage>`, prefixes `avatars/` and `pending/`.
- Keep set:
  - the `AuthGateClientId` output of `auth-gate-console-<stage>`;
  - the `AuthGateClientId` output of `auth-gate-portal-<stage>`;
  - the `AuthGateClientId` parameter of `auth-app-<stage>`.

  Each must exist as `C#<id>/META` with no `deletedAt` and no `disabledAt`, else stop before any delete.
- The typed confirmation is exactly `reset stg`. Without `--apply` nothing is deleted, in DynamoDB or S3.
- Unknown item shapes are kept and reported, never deleted.
- Operator profile `ADMIN_PROFILE` (default `default`), region `ap-southeast-1`. No secrets are involved. Never call real AWS in tests; never read `~/.aws`.
- English in code, docs and commits. Conventional Commits, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Gate: `pnpm run check`.

## Review Focus

1. The keep set points at a missing, soft-deleted or disabled client, or a stack output is empty or `None`: nothing is deleted. Pinned in Tasks 2 and 3.
2. An item whose pk prefix the rules do not know, in the AuthGate or Console table: it is kept, and the dry run prints it under `unknown`. Pinned in Task 1.
3. BatchWriteItem returns UnprocessedItems (throttling): retried with backoff. A final failure returns an error naming the table, and a rerun finishes the job. Pinned in Task 2.
4. The Console admins' factors `S#<consoleClient>#…` and their `ADMINS` items survive an apply. Pinned in Tasks 1 and 2.
5. A second apply deletes nothing. Pinned in Task 2.

### Task 1: The rules

**Files:**
- Create: `internal/reset/rules.go`, `internal/reset/rules_test.go`

**Interfaces:**
- Produces:
  - `type Table string` with constants `AuthGate`, `Console`, `Portal`, `AuthApp`.
  - `type Keep struct { Clients map[string]bool; Console string }`. `Console` is the Console's client id, whose factors are kept; it is also in `Clients`.
  - `func Decide(t Table, pk, sk, clientID string, k Keep) (label string, del bool)`. `clientID` is the item's `clientId` attribute; only `K#` items carry it, empty otherwise. `label` names the item type for the report.

Rules (spec §3):

| Table | Item | Label | Delete when |
|---|---|---|---|
| AuthGate | `C#<id>`/`META` | client | id ∉ Clients |
| AuthGate | `CLIENTS`/`C#<id>` | client-index | id ∉ Clients |
| AuthGate | `K#…`/`META` | key | clientID ∉ Clients (an empty clientID is deleted) |
| AuthGate | `S#<cid>#<sub>`/any | factor | cid ≠ Console |
| AuthGate | `RL#<cid>`/`META` | rate-bucket | cid ∉ Clients |
| AuthGate | `CH#<cid>#…`, `R#<cid>#…` | challenge, registration | cid ∉ Clients |
| AuthGate | `OWNER#…`/any | owner | always |
| AuthGate | anything else | unknown | never |
| Console | `ADMINS`/any | admin | never |
| Console | `SES#`, `JTI#`, `RL#`, `AUDIT#` prefixes | session, used-token, rate-bucket, audit | always |
| Console | anything else | unknown | never |
| Portal | any | the pk prefix up to `#` (or the whole pk) | always |
| AuthApp | any | the pk prefix up to `#` | always |

### Task 2: The runner and the command

**Files:**
- Create: `internal/reset/run.go`, `internal/reset/run_test.go` (DynamoDB Local, using `internal/platform/dynamo/dynamotest.NewTable`)
- Create: `cmd/stg-reset/main.go`

**Interfaces:**
- Consumes `Decide`, `Keep` and `Table` from Task 1.
- Produces:
  - `type Tables map[Table]string` (table names).
  - `type KeptClient struct{ ID, Name, RPID string }`.
  - `func CheckKeep(ctx context.Context, db *dynamodb.Client, authgate string, ids []string) ([]KeptClient, error)`. It errors if any id is empty, or its `C#<id>/META` is missing or has `deletedAt` or `disabledAt`.
  - `type Count struct{ Table Table; Label string; Kept, Deleted int }`.
  - `func Run(ctx context.Context, db *dynamodb.Client, tables Tables, k Keep, apply bool) ([]Count, error)`. In dry-run mode, `Deleted` means "would delete".
- `cmd/stg-reset`:
  - Flags: `-stage` (required; refuses anything but `stg`, exit 2), `-console`, `-portal`, `-authapp` (the three keep ids), `-apply`.
  - Tables are derived from the stage. It honours `$DYNAMO_ENDPOINT` like `cmd/prune-factors`.
  - It prints the kept clients (id, name, rpId), then one line per count: `<table> <label> kept=N <would delete|deleted>=M`, then a total. Without `-apply` and with a total above zero, it prints `rerun with --apply to delete them`.

- [ ] **Step 1: Write the failing tests** in `run_test.go`. Skip when `DYNAMO_ENDPOINT` is unset, as the other store tests do.
  - `TestRunApplyLeavesOnlyKept`: create four tables. Seed one item per rule line of Task 1, plus a few extra rows. Run with `apply=true`, scan every table, and assert the remaining keys equal the kept set exactly. Run again, and assert every `Deleted` is 0.
  - `TestRunDryRunDeletesNothing`: after a dry run, every seeded item is still there, and the counts equal those of the apply run.
  - `TestCheckKeepRefuses`: an empty id, a missing client, a client with `deletedAt` and a client with `disabledAt` each error. Three live clients return their names and rpIds.
  - A unit test with a fake BatchWriteItem that returns UnprocessedItems twice, then succeeds: all items are deleted. One that always returns them: an error naming the table. Put the batch writer behind a small interface so it can be faked.
- [ ] **Step 2:** Run `make test-store`, or `DYNAMO_ENDPOINT=http://localhost:8000 go test ./internal/reset/` with `docker compose up -d dynamodb`. Expected: FAIL.
- [ ] **Step 3: Implement.**
  - Scan with `ProjectionExpression: "pk, sk, clientId"` (aliasing names via ExpressionAttributeNames where needed) and `ConsistentRead: true`.
  - Batch the deletes in groups of 25, and retry UnprocessedItems with exponential backoff from 50ms, at most 8 attempts. Follow `internal/auth/factor/prune.go`.
  - Call `CheckKeep` in `main` before `Run`.
- [ ] **Step 4:** Run the tests. Expected: PASS. Run `go vet ./...`.
- [ ] **Step 5: Commit.** `feat(reset): scan, decide and batch-delete, with a checked keep set`.

### Task 3: The wrapper, the avatars and the docs

**Files:**
- Create: `scripts/setup-and-deploy/08-reset-data.sh`, `scripts/setup-and-deploy/test/08-reset-data.sh`; wire the test into `package.json` `test`.
- Modify: `docs/reference/deploy.md` (a section "Reset stg's user data").

**Interfaces:**
- Consumes `cmd/stg-reset` (Task 2).
- Produces `ADMIN_PROFILE=default scripts/setup-and-deploy/08-reset-data.sh [--apply]`.

**Behaviour:**
1. Source `lib.sh`. Refuse when `STAGE` is not `stg`.
2. Under `--profile "$ADMIN_PROFILE" --region "$REGION"`, read:
   - the Console's and the Portal's `AuthGateClientId` outputs;
   - auth-app's `AuthGateClientId` parameter (`describe-stacks --query "Stacks[0].Parameters[?ParameterKey=='AuthGateClientId'].ParameterValue"`);
   - the Portal's `AvatarBucket` output.

   Die if any value is empty or `None`.
3. Dry run: run `AWS_PROFILE="$ADMIN_PROFILE" go run ./cmd/stg-reset -stage "$STAGE" -console … -portal … -authapp …`, then `aws s3 rm "s3://$bucket/avatars/" --recursive --dryrun` and the same for `pending/`.
4. With `--apply`:
   - run the dry run first, so the operator sees what will go;
   - prompt `Type 'reset stg' to delete the items above:`, reading stdin;
   - any other answer or EOF: `nothing deleted`, exit 1;
   - on the exact answer, run the command with `-apply` and the two `s3 rm` calls without `--dryrun`;
   - print `done; run the four smokes`.
