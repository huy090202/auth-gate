# Continuous deploy to stg — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every push to `main` deploys AuthGate and the Console to stg from GitHub Actions through an OIDC role, then runs both smokes; old SAM artifacts expire after 30 days.

**Architecture:** Two admin scripts create the AWS side once (`scripts/ci/00-ci-role.sh`, `scripts/ci/00-sam-lifecycle.sh`). A `deploy` job in `.github/workflows/ci.yml` assumes the role, runs `scripts/ci/preflight.sh`, then the existing deploy and smoke scripts unchanged except for the `AWS_PROFILE` default in both `lib.sh`.

**Tech Stack:** bash, jq, AWS CLI v2, SAM CLI 1.169.0, GitHub Actions, actionlint (as a Go tool dependency).

**Spec:** `docs/superpowers/specs/2026-11-20-ci-deploy-design.md`

## Global Constraints

- No step calls AWS. The product owner runs both admin scripts and every deploy. Never touch `~/.aws`; tests set `HOME`, `AWS_CONFIG_FILE` and `AWS_SHARED_CREDENTIALS_FILE` to sandbox values, as `scripts/setup-and-deploy/test/99-purge.sh` does.
- Role name `ci-auth-gate-deploy`. It must not match `auth-gate-*`.
- Trust: `StringEquals` on `token.actions.githubusercontent.com:aud` = `sts.amazonaws.com` and `token.actions.githubusercontent.com:sub` = `repo:huy090202/auth-gate:ref:refs/heads/main`. No `StringLike`, no wildcard.
- Provider ARN: `arn:aws:iam::826113468815:oidc-provider/token.actions.githubusercontent.com`. Role ARN: `arn:aws:iam::826113468815:role/ci-auth-gate-deploy`.
- Policy attached to the role: the existing managed `auth-gate-deployer-policy`. `infra/deployer-policy.json` does not change.
- Lifecycle rule IDs start with `auth-gate-artifacts-`; filter prefix `auth-gate-`; 30 / 7 / 7 days as in spec section 4.
- Admin scripts take `ADMIN_PROFILE` (default `default`) and pass `--profile` explicitly, like `scripts/setup-and-deploy/00-deployer.sh`.
- stg only; `deploy` runs only on `push` to `refs/heads/main`.
- Secrets never on argv and never printed.
- English in code, comments, docs and commits. Conventional Commits, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `pnpm run check` must pass at the end of every task.

## Review Focus

- An existing lifecycle configuration with a top-level `TransitionDefaultMinimumObjectSize`: the write keeps it (pass `--transition-default-minimum-object-size`), or every other project's transitions change. Test in Task 1.
- A foreign rule in the legacy form (top-level `Prefix`, no `Filter`): passed through byte-for-byte as jq reads it, not normalised. Test in Task 1.
- An OIDC provider for GitHub that exists but lacks `sts.amazonaws.com` in its client IDs: the role script stops and prints the `add-client-id-to-open-id-connect-provider` command; it never changes a provider it did not create. Task 2.
- A developer shell that exports `AWS_ACCESS_KEY_ID` (temporary admin credentials, say): after Task 3 the scripts use those instead of the deployer profile. The README says so. Task 3.
- Two merges seconds apart: the second deploy waits for the first; nothing cancels a running `deploy`. Read in review of Task 3 (actionlint cannot see it).

### Task 2: OIDC provider and the CI role

**Files:**
- Create: `infra/ci-trust.json`
- Create: `scripts/ci/00-ci-role.sh`

**Interfaces:**
- Consumes: the managed policy `auth-gate-deployer-policy`, made by `00-deployer.sh`.
- Produces: role `ci-auth-gate-deploy` (ARN in Global Constraints), used by Task 3's workflow.

- [ ] **Step 1: Write `infra/ci-trust.json`**: one statement, `Effect Allow`, `Principal.Federated` the provider ARN, `Action sts:AssumeRoleWithWebIdentity`, `Condition.StringEquals` with exactly the two keys of Global Constraints.

- [ ] **Step 2: Write `scripts/ci/00-ci-role.sh`.** Source `scripts/setup-and-deploy/lib.sh`; `admin=(--profile "${ADMIN_PROFILE:-default}")`; require `jq`. In order:
  1. Account id from `sts get-caller-identity`; die if it is not `826113468815` (the trust file and policy name that account).
  2. Die unless `iam get-policy` finds `arn:aws:iam::<account>:policy/auth-gate-deployer-policy` ("run 00-deployer.sh first").
  3. Provider: `iam get-open-id-connect-provider` on the provider ARN. Absent (`NoSuchEntity`): `iam create-open-id-connect-provider --url https://token.actions.githubusercontent.com --client-id-list sts.amazonaws.com`. Check `aws iam create-open-id-connect-provider help` for whether `--thumbprint-list` is still required in this CLI; pass it only if it is, and say which in the report. Present but `ClientIDList` lacks `sts.amazonaws.com`: die printing the `add-client-id-to-open-id-connect-provider` command. Any other error: die.
  4. Role: `iam get-role`; absent → `iam create-role --role-name ci-auth-gate-deploy --assume-role-policy-document file://infra/ci-trust.json --max-session-duration 3600 --description "GitHub Actions deploy of auth-gate stg from main"`; present → `iam update-assume-role-policy` with the same file.
  5. `iam attach-role-policy` with the deployer policy ARN (idempotent).
  6. Print the role ARN.
