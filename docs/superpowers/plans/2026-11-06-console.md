# AuthGate Console and per-client rate limit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a token-bucket rate limit on AuthGate's verify role that is useful on its own, then the AuthGate admin API changes, then the AuthGate Console: a separate bilingual operator app in its own stack that manages clients and admin accounts without the browser ever holding the admin key.

**Architecture:** The limiter is one shared package (`internal/platform/ratelimit`) storing a bucket per key in DynamoDB. AuthGate gains list, patch, disable and enable, with an index item for listing. The Console is its own Go binary (`cmd/console`, `internal/console`) on a Function URL plus a React SPA in S3 behind one CloudFront distribution. It reaches AuthGate only over HTTP and holds server-side sessions in its own table.

**Tech Stack:** Go 1.26, aws-sdk-go-v2 (DynamoDB, SSM), aws-lambda-go + api-proxy `httpadapter.NewV2`, `golang.org/x/crypto/argon2`, `descope/virtualwebauthn` (tests), DynamoDB Local, React 19 + Vite 6 + Mantine 7.17 + react-router 7 (pnpm workspace package `console-web`), Vitest + jsdom, AWS SAM, CloudFront Functions, Bruno OpenCollection.

**Spec:** `/home/work/auth-gate/orchestrator/handoffs/feat-admin/spec.md`; Task 0 lands it at `docs/superpowers/specs/2026-11-06-console-design.md`.

The measurement showed it: 11 to 22 of 100 allowed. §10's "never exceeding the burst" is only an upper bound and did not catch this. The product owner chose the atomic spend (row 9). Task 3 Step 4 measures the result and stops for a decision if it misses the thresholds there.

## Verified facts

- **Client loading.** `KeyFunc` → `Authenticate` does `GetKey` then `GetClient`, both consistent, no cache; any store error is 401 (`client.go:199-230`). A `PATCH` or disable applies on the next request, and the limiter needs no extra client read.
- **Transactions.** No helper, no `TransactWriteItems` and no `Scan` anywhere in Go or the template. Only `BatchWriteItem` in `factor/store.go:272`. IAM for a transaction uses `PutItem`/`UpdateItem`/`DeleteItem`/`ConditionCheckItem`. AuthGate's Admin role already has what Task 4 needs. The Console adds `ConditionCheckItem`. DynamoDB Local ignores IAM, so only stg proves this.
- **Numbers.** `getN` uses `Atoi` and drops errors (`store.go:143`). A fractional `perSecond` or `tokens` read through it becomes 0, so add `getF`.
- **Config.** `config.Load` switches on `ROLE` (verify, admin, jwks, dev); `cmd/auth-gate/main.go` wires each. No new role here. The Console has its own binary and its own `LoadConfig`, not `platform/config`.
- **Argon2id.** `internal/auth/pin`: `argon2.IDKey`, `Params{Memory: 65536, Time: 3, Threads: 1}`, salt 16, key 32, stored as separate fields. `pin` imports `client`, so the Console copies the parameters rather than importing it.
- **CloudFront-Viewer-Address.** AWS docs: `AllViewerExceptHostHeader` (`b689b0a8-…`, already used on `/api/*` in both repos) includes "all device type and viewer location headers", and `CloudFront-Viewer-Address` is listed as a viewer location header, addable in an origin request policy. No custom policy needed. The docs state this by category, not by name, so Task 16 confirms it on stg. Docs show only `198.51.100.10:46532`; the IPv6 form is undocumented, so the parser tolerates both.
- **Adapter.** `httpadapter.NewV2` passes `Cookie` from `req.Cookies` and returns `Set-Cookie` through the v2 `cookies` array. It splits non-singleton request headers on commas, and sets `RemoteAddr` to the CloudFront edge IP, so never use `RemoteAddr` on AWS.
- **Deployer.** `auth-gate-deployer` has no data-plane rights on the table, no S3 outside SAM's bucket, no CloudFront Function, OAC or response-headers rights, and SSM only on `/credo/auth-gate/*`. `deployer-policy.json` is 3786 non-whitespace characters of the 6144 limit.
- **auth-app.** `mapError` falls through to `502 authgate_unavailable` (`bff/src/authgate/client.ts:147`), as the spec says.

## Review Focus

1. A key or temporary-password dialog dismissed with Esc, the backdrop or the X before confirming must stay open, or the only copy is lost (test in Task 14).
2. Rotating a client whose rate limit was changed or that is disabled must keep both, and the new key must stay 401 while disabled (tests in Tasks 2 and 4).
3. A browser tab left open while a master resets, clears or disables that admin must get `401 unauthorized` on the next call and land on sign-in, not on a blank or half-working screen (test in Task 7; guard in Task 13).
4. `PATCH /clients/{id}` with a case-variant key such as `{"Origins":[...]}` must still need step-up, because Go's JSON decoding is case-insensitive and AuthGate would accept it (test in Task 10).
5. A half session submitting another admin's `challengeId` must not spend that admin's PIN attempts, and a passkey `registrationId` from another session must not finish (tests in Task 9).

```
for attempt 0..2:
  consistent GetItem; on error → log, Allowed
  absent: tokens = burst, cond = attribute_not_exists(pk), next = nowµs
  present: tokens = min(burst, tokens + max(0, nowµs−read)/1e6 * perSecond)

  ok → Allowed; other error → log, Allowed
  condition failed and attempt<2 → sleep 5–25 ms jitter
return denied, RetryAfterSec = 1, Conflict = true
```

- Produces:
  ```go
  // dynamo
  func TransactWrite(ctx context.Context, c *dynamodb.Client, items ...types.TransactWriteItem) error
  func IsConditionFailed(err error) bool // ConditionalCheckFailedException, or TransactionCanceledException with a ConditionalCheckFailed reason
  // client
  var ErrBadCursor = errors.New("client: bad cursor")
  type Summary struct { ID, Name, RPID string; CreatedAt time.Time; DisabledAt *time.Time }
  type Patch struct { Name *string; Origins []string /* nil = unchanged */; PinPolicy *PinPolicy; TokenTTLSec *int; RateLimit *ratelimit.Settings }
  // Client gains DisabledAt *time.Time. Store: PutClient is replaced by:
  CreateClient(ctx, c Client) error                          // transaction: client (attribute_not_exists(pk)) + index item
  ListClients(ctx, cursor string, limit int32) ([]Summary, string, error) // newest first; cursor = base64url(clientId)
  SetDisabled(ctx, c Client, at *time.Time) error            // transaction: client (attribute_exists(pk)) + index
  // Service: List(ctx, cursor), Disable(ctx, id), Enable(ctx, id). service.Service: ListClients, DisableClient, EnableClient.
  ```
  Routes per spec §4; page size 50; the summary view is `{clientId, name, rpId, createdAt, disabledAt?}`; `nextCursor` omitted on the last page. `clientView` gains `disabledAt?`. Disable and enable ignore the body, so an empty one works. A bad cursor → `400 invalid_cursor`.

  Rules that are decided: `Update` merges into a `CreateInput` with the stored `rpId` and runs the existing `Validate`, so origins pass the suffix check; a zero `pinPolicy` field keeps the stored value. A `Name` change writes client and index in one transaction; other patches are a single conditional `UpdateItem`.
