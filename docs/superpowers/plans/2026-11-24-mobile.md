# Portal and Console on a phone — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** both apps are usable at 375 px wide, the incident path above all. That path is
sign in, open a client, rotate or disable it, pass step-up, then copy the new key.

**Architecture:** all layout lives in `packages/web-kit`:
- `shell-layout.tsx` gains a phone header and a Mantine `Drawer`;
- `shell.css` and `kit.css` gain the rules for 768 px and 640 px.

The apps change in four ways only:
- they pass the route and a menu icon to `ShellLayout`;
- they add two strings;
- they mark table cells with `data-label`, `cell-title` and `cell-actions`;
- they get the tests.

Wide screens must come out pixel-identical. Playwright screenshots taken before and after prove it.

**Tech Stack:** React 19, Mantine 7.17, Vite, vitest + jsdom. Playwright 1.65.1, run from
the npx cache, for the screenshots.

**Spec:** `docs/superpowers/specs/2026-11-24-mobile-design.md`

## Global Constraints

- Breakpoints:
  - the phone shell (header plus drawer) applies at `max-width: 768px`, the existing one;
  - tables-as-cards and the screen and dialog rules apply at `max-width: 640px`.
- At 769 px and above, nothing may change visually.
- CSP is `style-src 'self'`. No `<style>` element may be injected. `Drawer` already defaults to
  `lockScroll: false` in `packages/web-kit/src/theme.ts`; keep it that way.
- New strings, in `common` of both `portal-web/src/strings.ts` and `console-web/src/strings.ts`:
  - `openMenu`: EN `Open menu`, VI `Mở menu`;
  - `closeMenu`: EN `Close menu`, VI `Đóng menu`.
- Touch targets in the drawer (nav links, buttons) are at least 44 px tall.
- Inputs compute to `font-size: 16px` at 640 px and below. Below that, iOS Safari zooms on focus.
- Tests only where they carry a why (a comment `// Why:` above each test, as in the existing files).
- Code, comments and commits are in English, with Conventional Commits and the trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Gate before a task is done: `PATH="$HOME/go/bin:$PATH" pnpm run check` exits 0.
- Screenshots and the harness live in
  `/tmp/claude-1000/-home-work-auth-gate-feat-admin/10d18f5d-2ec9-4d7e-972e-dd75d759cceb/scratchpad/mobile-shots/`,

## Review Focus

1. **The phone's Back button while the drawer is open.** Expected: the route changes and the
   drawer closes. Test in Task 2.
2. **Rotating or resizing to wide with the drawer open.** Expected: the drawer closes, so no
   modal stays stranded on a desktop layout. Test in Task 2.
3. **Long values in a card at 375 px.** Expected: a 60-character client name, a long email, an
   rpId or a ULID wraps inside the card and never widens the page. Covered by the fixtures in
   Task 1 and the check in Task 5.
4. **Vietnamese labels, which are longer than English.** Expected: a card label and its value
   wrap and stay readable. Covered by the VI phone shots in Task 5.
5. **A table column renamed later.** Expected: the card label still matches the column header,
   because both come from the same string. Covered by the label tests in Task 3.

### Task 3: Tables become cards on a phone

**Files:**
- Modify: `packages/web-kit/src/shell.css` (the `.data-table` card rules at 640 px)
- Modify the cells in:
  - `portal-web/src/screens/Clients.tsx`, `Members.tsx` (both tables), `Audit.tsx`;
  - `console-web/src/screens/Clients.tsx`, `Admins.tsx`, `Audit.tsx`.
- Test:
  - `portal-web/test/table-labels.test.tsx` (create);
  - `console-web/test/table-labels.test.tsx` (create).

**Interfaces (markup contract):**
- Every `Table.Td` whose column has a visible header carries `data-label={<the same string expression as its Table.Th>}`.
- Each body row has exactly one title cell. It carries `className="cell-title"` (kept alongside
  existing classes), and CSS hides its label. The title cells are:
  - client name (both Clients tables);
  - member name;
  - invite email;
  - audit time (both Audit tables);
  - admin user.
- Cells under an empty or screen-reader-only header have no `data-label`. These are the Members
  and invite action cells, and the Console Audit `col-toggle` cell. The action cells and the
  Console Admins actions cell carry `className="cell-actions"`.
- The Console Audit `.row-detail` row stays a sibling. On a phone it renders flush under its
  card, as that card's bottom part.

**CSS at 640 px and below:**
- `.data-table thead` is visually hidden, but kept for screen readers.
- Each `tbody tr` is a block card with border, radius and padding.
- Each `td` is a two-column grid: a label from `attr(data-label)`, then the value. The value
  wraps with `overflow-wrap: anywhere`.
- `.cell-title` takes the full width in bold.
- `.cell-actions` takes the full width, with its buttons at `width: 100%`.
- The `.col-toggle` cell sits at the top-right of the card.
- `.table-wrap` stops scrolling sideways.
